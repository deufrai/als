# ALS v0.7.1 Documentation Plan

## Issue

ALS v0.7 and v0.7.1 will coexist in the user population.

The v0.7.1 release includes user-visible behavior changes, especially around
network address advertisement for the image server. These changes must be
documented without changing the existing v0.7 documentation, so users running
v0.7 do not see instructions for features that are not present in their build.

The `release/1.0` branch already prepared the website for multiple documentation
versions by keeping the v0.7 tree and adding a separate v1.0 tree. The v0.7.1
documentation work should reuse the same model.

## Current Website Model

The public website is authored as a Hugo site under `website/`, using the Docsy
theme.

User documentation is stored in language-specific content trees:

- `website/content/en/docs/v0.7/`
- `website/content/fr/docs/v0.7/`

English and French documentation are authored separately. They are not generated
from each other.

Pages use Hugo front matter for ordering and metadata, including:

- `title`
- `description`
- `author`
- `lastmod`
- `weight`
- `type`
- `categories`
- `tags`

The documentation uses Docsy/Hugo shortcodes, raw HTML where useful, colocated
images, and custom static assets.

## Versioning Pattern From release/1.0

The `release/1.0` branch keeps the v0.7 documentation tree intact and adds full
duplicated trees:

- `website/content/en/docs/v1.0/`
- `website/content/fr/docs/v1.0/`

It also updates `website/hugo.toml` so that:

- the main documentation menu points to the latest documentation version
- `params.versions` lists the available documentation versions
- the version menu exposes both the latest version and older versions

Weights are assigned by version block:

- v0.7 pages use the `70xxx` range
- v1.0 pages use the `100xxx` range

This keeps page ordering stable within each version while preventing mixed
ordering between different documentation versions.

## v0.7.1 Documentation Plan

### 1. Duplicate the v0.7 Documentation Trees

Create new documentation trees by copying the current v0.7 trees:

- `website/content/en/docs/v0.7/` to `website/content/en/docs/v0.7.1/`
- `website/content/fr/docs/v0.7/` to `website/content/fr/docs/v0.7.1/`

The original v0.7 trees should remain unchanged except for narrowly scoped
metadata changes if they become technically necessary.

### 2. Update v0.7.1 Front Matter

In the duplicated v0.7.1 trees:

- rename root titles and descriptions from v0.7 to v0.7.1
- update `lastmod` on pages changed for v0.7.1
- move page weights into a dedicated v0.7.1 range

Proposed v0.7.1 weight block:

- root: `71010`
- installation: `71200`
- quickstart: `71280`
- user guide: `71300`
- reference: `71340`
- release notes: `71550`

Subpages should preserve the existing relative ordering from v0.7 by applying
the same offset pattern inside the `71xxx` range.

### 3. Update Website Version Navigation

Update `website/hugo.toml` so that the main documentation menu points to v0.7.1:

- English: `/docs/v0.7.1/`
- French: `/fr/docs/v0.7.1/`

Add v0.7.1 to `params.versions` and keep v0.7 available.

Expected order for the v0.7.1 release branch:

- `v0.7.1`
- `v0.7`

When this work is later reconciled with the `release/1.0` branch, the expected
version order can become:

- `v1.0`
- `v0.7.1`
- `v0.7`

### 4. Update Download Instruction Links If Needed

If the public download buttons should target v0.7.1 artifacts, update
`website/static/js/download.js` so that download buttons open the v0.7.1
installation instructions.

This should be done only once the release artifact names and target URLs are
known.

### 5. Document v0.7.1 Network Changes Only In v0.7.1

Network rework documentation must be added only under the v0.7.1 documentation
trees.

Likely pages:

- `userguide/preferences/output/_index.md`
- `userguide/ui/controls/_index.md`
- `reference/modules/server.md`
- `releasenotes/_index.md`

Potentially update `quickstart/_index.md` only if the server or QR-code workflow
is part of the introductory path.

The v0.7 pages must not describe v0.7.1-only address selection or QR behavior.

### 6. Keep English And French Trees Aligned

For each page changed in English, apply the equivalent documentation update in
French.

Both languages should keep:

- matching paths
- matching weights
- matching feature coverage
- equivalent screenshots unless localized screenshots differ

### 7. Validate The Website

After authoring:

- build the Hugo site locally
- confirm the main documentation menu lands on v0.7.1
- confirm v0.7 remains accessible
- confirm v0.7 pages do not contain v0.7.1-only instructions
- confirm sidebar ordering within v0.7.1
- confirm language switching between English and French
- confirm version switching between v0.7.1 and v0.7

Pay particular attention to the version selector behavior, because the
`release/1.0` version selector tries to link from the current page to a matching
page in another documentation version.
